# LunaDesk 聊天、配置与本地历史改造设计

日期：2026-11-02

## 目标与范围

本轮解决系统返回键误退出、配置页拥挤、流式输出跳动、首页预制问题过多，以及本地对话历史缺失。视觉上参考 Codex App 的内容优先和轻量操作方式，但沿用 LunaDesk 的浅色基调，不照搬桌面布局。

## 页面结构

```text
聊天（首页）
  ├─ 侧边栏：新对话、历史对话、API 配置
  ├─ 历史对话：回看、改名、删除
  └─ API 配置：配置列表 → 配置编辑 → 模型选择
```

侧边栏只有一个“历史对话”入口。历史页按最近使用时间排序，同一列表显示全部记录；列表项展示标题、最后一条消息摘要和时间。搜索可放在列表顶部，记录多时仍能快速找到。

### 聊天首页

```text
┌──────────────────────────────────┐
│ ☰    对话标题 / 当前模型       ＋ │
├──────────────────────────────────┤
│                                  │
│      今天想聊什么？               │  空白时只显示简短引导
│                                  │
│  用户提问                        │
│  助手回答，按自然段阅读           │
│                                  │
│            ↓ 查看最新             │  离开底部时才出现
├──────────────────────────────────┤
│  输入问题…                  发送  │
└──────────────────────────────────┘
```

- 顶部只放菜单、会话标题/模型、新对话；不放消息计数或重置按钮。
- 移除目前三张大预制问题卡片。空白页只留一句引导文案；输入框始终是主入口。
- 用户消息用浅蓝灰气泡，助手内容以无边框正文呈现。复制操作在消息旁或长按菜单中提供。
- 图标使用统一的细线风格和浅蓝、青灰色，不使用近黑色图标；文字仍需保持清晰对比度。
- 以页面留白、字号和弱分割线区分层级，减少大面积卡片和高饱和色块。浅色是默认视觉方向。

### 历史对话

- 新消息发出时建立本地会话，默认取首条用户问题的简短内容作标题；用户改名后不再自动覆盖。
- 点击记录进入原对话并可继续提问；列表中的更多菜单提供“改名”和“删除”，删除前二次确认。
- 新对话只切换到空白会话，不删除旧记录；删除仅影响所选会话。
- 记录保存在本机应用私有空间。现有 Android 配置允许系统云备份，实现时需将对话数据库排除出云备份和设备迁移，避免“仅本地”与实际行为不一致。卸载 App 后历史不再保留；以后若要导出或迁移，再单独设计。
- 历史存储采用 Android 本机 SQLite 数据库，由系统自带的 `SQLiteOpenHelper` 管理，不增加 Room 依赖。数据库分为会话表（标题、创建和更新时间、摘要）与消息表（所属会话、角色、内容、状态、顺序）。现有 DataStore 只继续保存 API 配置。列表先读取会话摘要，打开时再读取消息，避免大量长对话拖慢首页。

### API 配置

- 一级页只展示配置名称、服务地址、当前模型及“新增”；每条配置的编辑、启用、删除收进更多菜单。
- 编辑页先显示名称、API 地址、密钥和当前模型。模型列表通过单独的选择页或弹层展开，支持搜索与刷新。
- 温度、最大输出等低频项放进“高级参数”折叠区。保存按钮固定在底部，测试连接作为次要操作。
- 字段错误就近提示；有未保存内容时返回仍显示放弃确认，避免误丢配置。

## 返回与滚动规则

系统返回键与页面左上角返回按钮遵循同一顺序：先关弹窗或侧边栏，再从模型选择回配置编辑、从配置编辑回配置列表、从配置列表或历史页回聊天。只有聊天首页且没有浮层时，返回键才交给系统退出。

流式输出仅在用户原本停留在底部时跟随。手指上滑阅读旧消息后立刻停止自动跟随；点击“查看最新”才重新启用。接收的文本分批刷新界面，滚动只对最新增量做轻量位置修正，不连续启动 250 毫秒动画。流式阶段减少 Markdown 重排，完成后再做完整排版。

## 实现边界与验证

1. 导航状态统一处理返回键和未保存确认，覆盖侧边栏、历史、配置和模型选择。
2. 本地历史单独建数据层；发送、停止、失败、切换会话时保证消息状态能恢复，删除和改名只操作指定会话。
3. 修改聊天与配置 Compose 页面，统一图标、触控区域和浅色层级。
4. 为历史存取、导航返回、流式跟随边界补充针对性测试；执行单元测试、Debug APK 构建和签名验证。可连接设备时再做返回键与长回复的真机检查。
5. 已确认 Tailscale 中的 Android 设备 `Xiaomi 15` 在线且支持文件发送。完成构建后把已验证 APK 发到该设备，并核对发送结果。安装覆盖还需依据当前手机上的签名和 `versionCode` 判断。

此设计会调整会话主流程和本地数据结构，属于核心流程改动。实现前需要按项目约定确认方案。
