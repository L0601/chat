# 对话用量与性能统计设计

## 目标

每次 AI 回答完成后，在该回答下方展示输入 token、输出 token、输出速度和首字耗时；聊天顶部提供当前会话的汇总，数据缺失时按字段隐藏。继续使用浅色界面，不压缩主要阅读区域。

## 页面展示

回答正文下方使用一行小字，空间不足时自然换成两行，字号不低于 12sp，颜色采用可读的蓝灰色：

```text
助手回答正文……

输入 1,280 · 输出 360 token
速度 45.0 token/秒 · 首字 0.8 秒
```

只展示有数据的项。生成中不持续刷新统计，完成后一次显示；手动停止或请求失败时，已有可靠数据可显示为“已停止”或“未完成”，不将未知数据写成 0。复制按钮和正文保持现有行为。

顶部保留对话标题与当前模型；存在至少一项有效会话统计时，在标题栏下增加可点击的一行摘要，使用小字号和轻分隔线：

```text
☰   对话标题 / 当前模型                   ＋
    本会话  输入 4,000 · 输出 400 · 80 token/秒  ›
```

点击摘要打开底部弹层，展示输入和输出 token 合计、加权输出速度、加权首字耗时，以及各项有效调用数。例如“输出速度 80.0 token/秒（2 次）”。弹层解释加权口径；统计不足时不展示该项。小屏幕或系统大字体下摘要可省略次要数字，完整数据仍在弹层中。没有任何有效统计时，摘要行和弹层入口都不显示。

## 数据与计算

- **输入、输出 token**：优先使用服务端实际返回的 `prompt_tokens` 和 `completion_tokens`；分别允许缺失。不按字符数估算。输入包含该次请求发送的上下文，因此多轮会话的输入总量包含重复发送的历史内容。
- **首字耗时**：用单调时钟测量，从实际发起本次 HTTP 请求到收到第一个非空的可见文本片段。它包含网络和服务端等待，不代表纯模型推理时间；纯空白片段不作为首字。无可见文本或回退到非流式响应时不显示，重试后以实际返回内容的请求作为计时起点。
- **输出速度**：使用服务端输出 token 数除以客户端接收首个到最后一个非空可见文本片段的时间间隔，标注为估算值。仅在有可靠输出 token 数、至少两个可见文本片段且时间间隔足够大时计算。结果受网络分块、缓冲及可能的隐藏推理 token 影响，不能当作服务端纯推理速度。非流式回复不能测出首字到末字的流式速度，因此不展示此项。
- **会话 token 合计**：分别累加有数据的已完成调用，并显示各自有效调用数；如果部分已完成调用缺少用量，标明“部分调用有数据”，避免误认为完整账单。
- **会话加权速度**：只使用同时具备输出 token 数和有效输出时长的已完成调用，计算 `这些调用的输出 token 合计 ÷ 这些调用的输出时长合计`。例如 100 token / 2 秒和 300 token / 3 秒，汇总为 400 / 5 = 80 token/秒，而不是简单平均 50 和 100。
- **会话加权首字耗时**：只使用同时具备首字耗时和正数输入 token 的已完成调用，按输入 token 加权：`Σ(首字耗时 × 输入 token) ÷ Σ输入 token`。因此上下文更长的请求占更大权重；有首字耗时但缺输入 token 的调用仍可显示单次数据，不纳入此加权值。
- 取消、失败或中断的调用保留其已收到的可靠信息，但不纳入已完成调用的汇总。模型切换后历史仍保留原模型；会话汇总覆盖该会话内的所有模型，并在详情中提示可能混合模型。

## 接口兼容与保存

现有 OpenAI 兼容流式接口需要在支持时请求 `stream_options.include_usage`，同时兼容非流式响应中的 usage；部分服务不支持这一参数或不返回用量，应按配置或明确的参数拒绝响应安全降级，不能因为超时等不确定结果自动重复请求。应继续读取到最终使用量事件或流结束，而不是遇到 `finish_reason` 就立刻停止。流中断可能没有最终 usage，缺失项直接隐藏。

统计和对应助手消息一起保存在 SQLite 中；增加数据库版本和迁移，老记录的统计字段为空，不破坏历史内容。回看时还原单次统计并按同一口径计算会话汇总；删除会话时同步删除统计。计时使用单调时钟的持续时间，持久化时只保存时长，不保存单调时钟原始时间戳。

## 验证

覆盖最终 usage 位于 finish_reason 之后、缺失 usage、空白首片段、非流式回退、取消/错误、极短输出、多模型、部分统计及数据库升级与历史恢复。检查不同屏幕宽度和大字体下不遮挡消息、操作按钮或输入框，再构建并在手机上检查流式交互。
